# Contributing to CorePrep AI

Thank you for considering a contribution to CorePrep AI.

## Before making a change
1. Read the root README and the relevant documentation.
2. Identify the feature area affected by your change.
3. Check existing issues or discussions to avoid duplicating work.
4. Keep the change focused and avoid unrelated formatting changes.

## Suggested workflow
1. Create a branch for the task.
2. Make a small, understandable change.
3. Test the affected frontend or backend behavior.
4. Update documentation when behavior or setup instructions change.
5. Review the final diff and remove temporary files.
6. Commit with a clear message.

## Commit message examples
- `docs: clarify local setup instructions`
- `docs: add architecture overview`
- `docs: document API endpoints`
- `fix: handle invalid assessment input`

Use a message that accurately describes the change. Do not create commits that claim work that was not performed.

## Documentation contributions
Documentation should:
- Match the current implementation.
- Distinguish verified behavior from planned behavior.
- Use placeholders instead of real secrets or personal data.
- Include commands that have been checked for the target operating system.
- Be updated alongside relevant code changes.

## Testing
Run the checks already defined by the project. If a check cannot be run locally, say so clearly in the pull request rather than claiming it passed.

## Pull request description
A useful pull request explains:
- What changed
- Why the change was needed
- How it was tested
- Any known limitations
